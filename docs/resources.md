# Resource providers

Resource transport and content semantics are independent. The engine interprets JSON as options, usage examples or imported catalogs; ResourceProvider only fetches bounded bytes.

## Configuration contract

Each resource ID has exactly one endpoint field:

| Field | Meaning |
|---|---|
| uri | Workspace-relative file URI/path or HTTPS URL |
| uriEnv | Environment variable containing the endpoint, useful for presigned URLs |
| bearerTokenEnv | Optional environment variable containing a bearer token |
| sha256 | Optional 64-character SHA-256 digest of the exact response bytes |

Local files must resolve inside the workspace, including symlink resolution. Do not put tokens in committed URI strings. Files can be in any explicitly referenced repository directory; they do not need to be generated by Pandora.

The HTTPS provider uses GET, accepts HTTP 200, refuses redirects, limits the body to 5 MiB, uses a 10-second connection timeout and a 20-second overall request timeout. It does not forward credentials to a redirected host. Supply the final endpoint. Production does not enable plaintext HTTP. Integration tests use an explicitly constructed loopback-only HTTP provider.

A first-party S3 SDK is not required for an object served over HTTPS. Public objects or presigned URLs can be used today. Private IAM/SigV4 access, Azure Blob credentials, or custom artifact stores require an additional provider.

## CI publication pattern

1. Generate option/example JSON in the producer's normal build pipeline.
2. Validate its shape and compute the exact content's SHA-256.
3. Publish it to an immutable versioned URL in an existing artifact store.
4. Update the consumer's named resource URI and optional digest through normal code review.
5. Run Pandora scan/validate in the consumer.

Pandora does not create buckets, upload artifacts, manage access policies or obtain credentials. It consumes the URLs already published by your pipeline.

All configured resources are fetched once per scan, including when --if-stale is supplied. The resource content digests participate in scan freshness. A failed download, invalid JSON, digest mismatch, missing authentication or unsupported transport fails the scan and preserves the last successful generation. There is no silent online fallback to stale cache.

## Offline behavior

Validated remote payloads are cached under pandora/cache/resources using a hash of resource identity, endpoint, digest and credential environment-variable name. Raw endpoint strings and credentials are not stored as cache metadata. Payloads themselves are ordinary local JSON and may contain private framework information; keep generated/cache directories out of version control.

--offline reads these cache files and rechecks JSON and any pinned digest. It never goes online to fill a missing cache. Offline mode cannot refresh an expired or changed remote resource. Changing a presigned URL changes its cache key. To keep a stable offline artifact, use a stable endpoint or a repository file.

Changing a token does not invalidate a cached payload under the same endpoint/resource ID. For reproducible shared metadata, pin SHA-256. Credentials authorize network retrieval; the offline cache is already a local copy.

## Custom transport

Implement io.cyborgcode.pandora.spi.ResourceProvider:

```java
boolean supports(URI uri);
byte[] read(URI uri, Path workspace, Map<String,String> headers, int maxBytes)
    throws IOException;
```

Register the implementation with META-INF/services/io.cyborgcode.pandora.spi.ResourceProvider in a JAR, then add that JAR through PANDORA_EXTRA_CLASSPATH when using the launcher. Built-in file/HTTPS transports are selected first. Use a distinct scheme, such as s3://bucket/key, for a new provider.

Providers must honor the byte limit, set their own bounded timeouts, avoid leaking credentials/URIs through exceptions, and throw on failure. The loader still validates JSON and the configured digest. A resource-provider plug-in is trusted executable Java code; installing one is distinct from reading example JSON.

For a native S3 provider, let the AWS SDK default credential chain resolve local/CI credentials. Keep the AWS dependency inside its own module and preserve the same resource configuration contract. This module is an extension point, not included in version 0.1.
